# SPEC: ステータスライン再設計

## 概要
`user\statusline.py` をゼロベースで作り直す。目的は、情報過多・縦幅・配色の不満を解消し、見やすく、状況に応じて表示が変わるステータスラインにすること。

## 表示仕様

### レイアウト（3行）
```
◆ Sonnet 5.5 / high │ ⎇ main ● │ ⇄ PR #12 pending
▸ C:/Users/<ユーザー名>/OneDrive/github/my-claude
◔ 32% ▓▓░░░ │ ⏱ 65% ▓▓▓░░ 2h10m │ ▦ 85% ▓▓▓▓░ 1d4h │ ✎ statusline
```
- 1行目（モデルと Git）: モデル名 / effort、ブランチ（未コミットがあれば `●`）、PR/MR（番号とレビュー状態）。
- 2行目（場所）: ディレクトリ（フルパス、`/` 区切り）。
- 3行目（使用量とセッション）: ctx、5時間枠（残り時間付き）、7日枠（残り時間付き）、セッション名（末尾）。
- 区切りは `│`（灰色）。

### 項目と表示条件
| 項目 | 記号 | 表示条件 |
|---|---|---|
| モデル + effort | ◆ | 常時 |
| ディレクトリ | ▸ | 常時（フルパス） |
| Git ブランチ | ⎇ | git リポジトリ内のみ。未コミットは `●`（黄） |
| PR/MR | ⇄ | あるときのみ |
| セッション名 | ✎ | あるときのみ |
| コンテキスト使用率 | ◔ | 常時 |
| 5時間枠 | ⏱ | レート制限の情報が取れるときのみ |
| 7日枠 | ▦ | レート制限の情報が取れるときのみ |

- メーターは「数値 + 5文字のバー」（`▓` と `░`）。5h/7d は残り時間を添える（括弧なし）。
- コスト・追加/削除行数・プロンプトキャッシュ残りは**廃止**する（常時も条件付きも表示しない）。

### 配色（ANSI 16色、端末テーマ追従）
- モデル/effort、セッション名: シアン
- ディレクトリ、PR/MR: 青
- ブランチ: 緑、未コミット印: 黄
- 区切り・残り時間: 灰色
- 使用率（ctx / 5h / 7d 共通）: 60% 未満は緑、60% 以上は黄、80% 以上は赤。記号・数値・バーを同じ色にする。
- PR のレビュー状態: approved は緑、changes_requested は赤、それ以外は黄。

## 流れ（動作）
1. Claude Code が JSON を標準入力で渡す。
2. `statusline.py` が値を読み、項目を組み立てて 2 行を出力する。取れない項目は出さない。
3. 実行は `py {{HOME}}/.claude/statusline.py`（`settings.json` の `statusLine.command` は現行どおり）。`refreshInterval` は現行の 30 秒を維持する。
4. `user\statusline.py` を編集し、`sync.ps1` で `~\.claude\` に反映する。

## 受入条件
- 標準入力が空や不正な JSON でも、例外で落ちず、表示が出る（取れない項目は省略）。
- 3行を超えない。ディレクトリは2行目、セッション名は3行目の末尾に出る。
- git リポジトリ外ではブランチ項目が出ない。
- 使用率 59/60/79/80% で緑/黄/黄/赤に切り替わる。
- レート制限の情報がないとき、5h/7d が出ない。
- Python 標準ライブラリのみで動き、`py` ランチャー経由で実行できる。
- Windows の実端末（Claude Code 上）で、記号の表示崩れがないことをユーザーが確認する。

## 非目標
- Nerd Font 専用アイコンの使用。
- コスト・行数・キャッシュ残りの表示。
- トゥルーカラーや 256 色の使用。
- macOS / Linux への対応。
- スキル/プラグインの追加（リポジトリの管理対象外）。
- `settings.json` の `statusLine` 設定の変更（コマンドと `refreshInterval` は現行維持）。

## リスク
- `⎇` `◔` `⏱` `▦` `⇄` `✎` などは、フォントによって幅がずれる/欠ける可能性がある（未確認）。実機で崩れたら、記号を差し替える（文字ラベルのみの案 A に戻す）。
- ディレクトリがフルパスなので、深い階層では 2 行目が端末幅で折り返す恐れがある（単独の行なので他の項目への影響は小さい）。
- 3行にしたため、縦幅は現行と同じ（Q2 で挙げた縦幅の不満は解消されない）。
- git の呼び出しは表示のたびに実行される（タイムアウト 3 秒）。リポジトリが大きいと遅くなる恐れがある。
- レート制限や PR などの入力フィールド名は、現行コードが読んでいる名前を踏襲する。仕様変更があれば表示されなくなる。

## 決定ログ
- 目的: 見やすさ + 状況に応じた動的な振る舞い（Q1: B）。
- 困りごと: 情報過多・縦幅・配色（Q2）。
- 制約: 既存の運用（`py` + `sync.ps1`）、標準ライブラリのみ（Q3）。
- 常時表示: モデル、ディレクトリ、ブランチ、ctx、5h、7d、PR、セッション名（Q4）。
- Nerd Font なし（Q5）。
- セッション名は使用量の行（最終的に3行目）の末尾に置く（最終確認 v1 の修正コメント）。
- 当初は2行構成（Q7: B）。最終確認 v2 の修正でディレクトリを独立した行にして3行構成にし、v3 の修正で2行目と3行目を入れ替えた（ディレクトリが2行目、使用量とセッション名が3行目）。メーターは短いバー + 数値（Q8）。
- ディレクトリはフルパス（Q9）。独立した2行目に置く（最終確認 v2・v3 の修正コメント）。
- 配色は ANSI 16色（Q11）、しきい値は全メーター共通 60/80（Q12）。
- アイコンは Unicode 記号（Q15: B）。
- コスト・行数・キャッシュは廃止（Q13: D, Q16: A）。Q6 の「条件付き表示」は PR とセッション名にのみ適用。
- レート制限が取れないときは非表示（Q14: A）。
