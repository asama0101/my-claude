# SPEC: ステータスライン再設計

実装は `user\statusline.py`。この SPEC は 2026-10-10 の見直し後の現状に合わせてある（当初の合意からの変更点は「決定ログ」を参照）。

## 概要
`user\statusline.py` をゼロベースで作り直した。目的は、情報過多・縦幅・配色の不満を解消し、見やすく、状況に応じて表示が変わるステータスラインにすること。

## 表示仕様

### レイアウト（2行）
```
🤖 Sonnet 5.5 / high │ 📁 C:/Users/<ユーザー名>/OneDrive/github/my-claude │ 🌿 main ● │ 🔀 PR #12 approved
💬 ctx 32% ▓▓░░░ │ ⏳ 5h 65% ▓▓▓░░ 2h2m │ 📅 7d 85% ▓▓▓▓░ 1d3h │ 🏷 statusline
```
- 1行目（モデルと場所）: モデル名 / effort、ディレクトリ（フルパス、`/` 区切り）、ブランチ（未コミットがあれば `●`）、PR/MR（番号とレビュー状態）。
- 2行目（使用量とセッション）: ctx、5時間枠（残り時間付き）、7日枠（残り時間付き）、セッション名（末尾）。
- 区切りは `│`（灰色）。

### 項目と表示条件
| 項目 | アイコン | 表示条件 |
|---|---|---|
| モデル + effort | 🤖 | 常時（取れなければ `?`） |
| ディレクトリ | 📁 | あるときのみ（フルパス） |
| Git ブランチ | 🌿 | git リポジトリ内のみ。未コミットは `●`（黄） |
| PR/MR | 🔀 | あるときのみ |
| セッション名 | 🏷 | あるときのみ |
| コンテキスト使用率（ラベル `ctx`） | 💬 | 常時（取れなければ `ctx --`） |
| 5時間枠（ラベル `5h`） | ⏳ | レート制限の情報が取れるときのみ |
| 7日枠（ラベル `7d`） | 📅 | レート制限の情報が取れるときのみ |

- メーターは「アイコン + ラベル + 数値 + 5文字のバー」（`▓` と `░`）。5h/7d は残り時間を添える（括弧なし）。
- コスト・追加/削除行数・プロンプトキャッシュ残りは**廃止**する（常時も条件付きも表示しない）。

### 配色（ANSI 16色、端末テーマ追従）
意味のある色だけを使い、それ以外は白と灰色にする。
- 使用率（ctx / 5h / 7d 共通）の数値とバー: 60% 未満は緑、60% 以上は黄、80% 以上は赤。
- 未コミット印 `●`: 黄。
- PR/MR のレビュー状態: approved は緑、changes_requested は赤、それ以外は黄。
- 白: モデル名（太字）、effort、ディレクトリ、ブランチ名、PR/MR 番号。
- 灰色: 区切り、メーターのラベル（`ctx` / `5h` / `7d`）、残り時間、セッション名、`--`。
- 絵文字の色は端末が決めるため、制御できない。

## 流れ（動作）
1. Claude Code が JSON を標準入力で渡す。
2. `statusline.py` が値を読み、項目を組み立てて 2 行を出力する。取れない項目は出さない。
3. 実行は `py {{HOME}}/.claude/statusline.py`（`settings.json` の `statusLine.command` は現行どおり）。`refreshInterval` は現行の 30 秒を維持する。
4. `user\statusline.py` を編集し、`sync.ps1` で `~\.claude\` に反映する。

## 受入条件
- 標準入力が空や不正な JSON でも、例外で落ちず、表示が出る（取れない項目は省略）。
- 2行を超えない。ディレクトリは1行目、セッション名は2行目の末尾に出る。
- git リポジトリ外ではブランチ項目が出ない。
- 使用率 59/60/79/80% で緑/黄/黄/赤に切り替わる。
- レート制限の情報がないとき、5h/7d が出ない。
- Python 標準ライブラリのみで動き、`py` ランチャー経由で実行できる。
- Windows の実端末（Claude Code 上）で、絵文字の表示崩れがないことをユーザーが確認する。

## 非目標
- Nerd Font 専用アイコンの使用。
- コスト・行数・キャッシュ残りの表示。
- トゥルーカラーや 256 色の使用。
- macOS / Linux への対応。
- スキル/プラグインの追加（リポジトリの管理対象外）。
- `settings.json` の `statusLine` 設定の変更（コマンドと `refreshInterval` は現行維持）。

## リスク
- 絵文字は、端末やフォントによって幅がずれる/欠ける可能性がある（未確認）。崩れたら、Unicode 記号または文字ラベルのみに戻す。
- ディレクトリがフルパスで 1 行目に入るため、深い階層やブランチ・PR が付いた状態では 1 行目が端末幅で折り返す恐れがある。
- git の呼び出しは表示のたびに実行される（タイムアウト 3 秒）。リポジトリが大きいと遅くなる恐れがある。
- レート制限や PR などの入力フィールド名は、現行コードが読んでいる名前を踏襲する。仕様変更があれば表示されなくなる。

## 決定ログ
- 目的: 見やすさ + 状況に応じた動的な振る舞い（Q1: B）。
- 困りごと: 情報過多・縦幅・配色（Q2）。
- 制約: 既存の運用（`py` + `sync.ps1`）、標準ライブラリのみ（Q3）。
- 常時表示: モデル、ディレクトリ、ブランチ、ctx、5h、7d、PR、セッション名（Q4）。
- Nerd Font なし（Q5）。
- メーターは短いバー + 数値（Q8）。配色は ANSI 16色（Q11）、しきい値は全メーター共通 60/80（Q12）。
- コスト・行数・キャッシュは廃止（Q13: D, Q16: A）。Q6 の「条件付き表示」は PR とセッション名にのみ適用。
- レート制限が取れないときは非表示（Q14: A）。
- 最初の合意（最終確認 v4）は 3 行構成・Unicode 記号（Q15: B）だった。
- 実装後の見直し（2026-10-10）で次の 4 点を変更した。
  - メーターに文字ラベル（ctx / 5h / 7d）を付け、ラベルを項目ごとの固定色にした（メーターの見分けがつかない、色が全部同じで区別できない、という指摘）。
  - アイコンを絵文字に変更した。ctx は 🧠 から 💬 にした。
  - レイアウトを 2 行に戻した（ディレクトリは 1 行目）。
  - これらは SPEC の承認フロー（roundtable）を経ず、質問への回答（選択式）で決めた。
- 配色を見直し（「カラフルすぎる」という指摘）、メーターのラベルの固定色を廃止して灰色にした。シアン・青・マゼンタは使わず、意味のある色（使用率、未コミット印、レビュー状態）だけ残した。
