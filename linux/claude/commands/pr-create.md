---
description: 変更をコミット→push→PR作成まで一括実行する
---

現在のブランチの変更をコミットし、push してPRを作成する。

## 手順

1. 次を並行で実行し、現状を把握する。
   - `git status`（未追跡ファイルの確認。`-uall`は使わない）
   - `git diff` と `git diff --staged`（差分内容の確認）
   - `git log --oneline -10`（このリポジトリのコミットメッセージの書き方を踏襲するため）
   - `git branch --show-current`

2. 現在のブランチが `main`/`master` の場合は、コミットせず停止し「先にフィーチャーブランチを作成してください」と伝える（main-branch-guard.sh によりどのみち書き込みはブロックされる）。

3. 未コミットの差分が無く、かつリモートに対して未pushのコミットも無い場合は「差分なし」と報告して停止する。

4. 未コミットの差分がある場合、簡潔（1〜2文、Why中心）なコミットメッセージを作成する。`.env`・認証情報等の機密ファイルが含まれていないか確認する。

5. 差分の要約とコミットメッセージ案をユーザーに提示し、「この内容でコミット→push→PR作成まで進めてよいか」の1回の承認を得る。

6. 承認後:
   a. 該当ファイルのみを `git add`（`-A`/`.` は使わない）
   b. コミット（Co-Authored-By トレーラーを付与、セッションの規約に従う）
   c. `git push -u origin <branch>`
   d. ベースブランチから分岐して以降の全コミット（`git log [base]...HEAD`・`git diff [base]...HEAD`）を確認し、PRタイトル（70字以内）とSummary/Test planを含むPR本文を作成
   e. `gh pr create` でPRを作成する

7. 作成されたPRのURLを報告する。

## 禁止事項

- `git push --force`、`--no-verify`、`--no-gpg-sign` は使わない
- コミットは新規作成のみ（`--amend` は明示的に指示された場合のみ）
- 差分レビューを飛ばして自動的にコミット・pushしない（手順5の承認は必須）
