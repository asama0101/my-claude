# 可読性の書き方原則

執筆時の可読性原則（要約先出し・段落設計・箇条書き/散文/表/図の使い分け・見出し階層・5W1Hの網羅）は `~/.claude/agents/references/doc/writing.md` を参照する。本ファイルでは重複させず、docwright 固有の補足のみを記す。

## docwright 固有の注意点：読者粒度の差が大きい

docwright は17種類の文書を扱い、種類ごとに読者層の粒度差が大きい。同じ「可読性が高い文書」でも、読者が変われば求められる前提知識・文体は別物になる。

- **新規参加者向け文書（README・開発環境構築手順書等）**: 前提知識ゼロを想定する。専門用語は初出時に説明し、手順は迷わず追える具体性で書く。
- **オンコール担当向け文書（Runbook・障害対応手順書等）**: システムの前提知識は既にあるものとして省略し、パニック下でも一手順ずつ実行できる短さ・具体性を優先する。Why の説明は最小限にとどめ、What と How を前面に出す。
- **開発担当向け文書（設計書・ADR等）**: Why（設計判断の背景）を厚く書く。手順の網羅性より、判断根拠の追跡可能性を優先する。

執筆前に「この文書を最初に開くのは誰か」を1文で明確にし、上記のどの粒度に近いかを判断してから書き始める。
