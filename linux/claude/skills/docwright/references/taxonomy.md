# 文書体系（17タイプ）

`docwright:create`・`docwright:update`・`docwright:audit`が共通で参照する体系定義。文書タイプの追加・削除はこのファイルだけを更新すればよい。

| フェーズ | 文書タイプ | agent名 | 目的 | 想定読者 |
|---|---|---|---|---|
| 企画・要件 | 要件定義書 | `docwright:requirements` | 業務・機能・非機能要件の確定 | 発注者・PM・開発者 |
| 設計 | 基本設計書（外部設計） | `docwright:basic-design` | 画面・外部IF・論理設計 | 開発者 |
| 設計 | 詳細設計書（内部設計） | `docwright:detailed-design` | モジュール内部処理・物理設計 | 実装担当 |
| 設計 | アーキテクチャ設計書 | `docwright:architecture-design` | 技術方式・非機能要件の実現方式 | 開発者 |
| 設計 | ADR | `docwright:adr` | 設計判断の背景と比較検討 | 開発者 |
| 設計 | セキュリティ設計書 | `docwright:security-design` | 認証・認可・暗号化・脆弱性対策 | セキュリティ担当 |
| 設計 | データモデル／データ辞書 | `docwright:data-model` | データ構造・属性・コード体系 | 開発者・運用担当 |
| 設計 | 監視設計書（SLO/SLI） | `docwright:monitoring-design` | 監視項目・閾値・通知ルール | SRE・運用担当 |
| 設計 | ログ設計書 | `docwright:logging-design` | ログ粒度・出力形式・保管期間 | 開発者・運用担当 |
| 実装 | README／セットアップガイド | `docwright:readme` | 全体像把握・環境構築 | 新規参加者 |
| 実装 | API仕様書 | `docwright:api-spec` | インターフェース契約 | API利用者 |
| テスト | テスト計画書 | `docwright:test-plan` | テスト観点・範囲・方式 | QA・PM |
| テスト | テスト仕様書 | `docwright:test-spec` | テストケース・合否基準 | QA |
| 運用 | 運用手順書 | `docwright:ops-manual` | 定常運用作業 | 運用担当 |
| 運用 | 障害対応手順書（Runbook） | `docwright:runbook` | 障害時の対応手順 | オンコール担当 |
| 運用 | 保守・引継ぎ資料 | `docwright:handover` | 知識移転・属人化排除 | 後任担当 |
| 利用者向け | ユーザーマニュアル | `docwright:user-manual` | 操作説明 | エンドユーザー |

agent名の`docwright:`以降の部分（`requirements`, `adr`等）が、`/docwright:create`・`/docwright:update`・`/docwright:audit`の引数として受け付ける文書タイプ指定値。引数がこの17個のいずれとも一致しない場合は、推測でdispatchせず一覧を提示してユーザーに再指定を求める。

## 判定チェックリスト（引数なし呼び出し時の自動判定）

| 文書タイプ | 候補に入れる条件（Yesなら候補） | 確認する場所 |
|---|---|---|
| 要件定義書 | 要件を記した文書が既存に無い、または今回スコープが新規機能追加で要件が未確定 | `docs/`配下の既存文書、Issue/チケット |
| 基本設計書 | 画面(UI)または外部公開IFが存在する | フロントエンドディレクトリ、ルーティング定義 |
| 詳細設計書 | 実装が複数モジュールに分割され内部処理フローの説明が要る規模 | ディレクトリ構成、モジュール数 |
| アーキテクチャ設計書 | 複数コンポーネント/サービス構成、または重要な技術選定が複数ある | docker-compose、IaC、複数言語/フレームワーク混在 |
| ADR | git log・PRに複数選択肢を比較した形跡がある、または今回の変更が後戻りコスト高 | git log、既存`docs/adr/` |
| セキュリティ設計書 | 認証/認可コード・暗号化・シークレット管理コードが存在する | authミドルウェア、envのシークレット参照 |
| データモデル | DBスキーマ・ORMモデル・マイグレーションファイルが存在する | `migrations/`、ORM定義 |
| 監視設計書 | メトリクス収集/監視コードがある、または本番運用がある | 監視系依存パッケージ、既存ダッシュボード定義 |
| ログ設計書 | ロガー導入済みで出力箇所が一定数以上 | loggerライブラリのimport数 |
| README | 常にYes（無ければ最優先） | リポジトリ直下 |
| API仕様書 | HTTPエンドポイント定義がある | ルーター/OpenAPI定義の有無 |
| テスト計画書 | テストディレクトリ/CI定義があり、かつ規模が計画書を要するレベル | `tests/`、CI設定 |
| テスト仕様書 | テストコードがあり、ケース一覧化が要求されている | 既存テストの粒度 |
| 運用手順書 | デプロイスクリプト/IaC/定期実行(cron等)がある | デプロイ関連ファイル |
| 障害対応手順書 | 監視・アラート・オンコール運用がある | アラート通知設定 |
| 保守・引継ぎ資料 | **自動判定しない**。ユーザーが引継ぎイベントを明示的に依頼した場合のみ`/docwright:create handover`として個別に候補へ入れる | ユーザーへの直接確認 |
| ユーザーマニュアル | エンドユーザー向けUIが存在する | フロントエンドの有無 |

## dispatch順序の注意

`docwright:readme`はドキュメント目次を他文書の存在に基づいて構築するため、他の文書タイプと同時に候補へ入った場合は必ず最後にdispatchする。
