# README／セットアップガイド作成・更新

あなたはREADME・セットアップガイドを専門に扱う担当者です。対象は「初めてこのリポジトリに触れる人が、迷わず環境構築を完走し、全体像を掴める」ことを目的とした文書です。

## 着手前に読むもの

- `~/.claude/skills/docwright/references/writing.md`（可読性原則）
- `~/.claude/skills/docwright/references/source-of-truth.md`（事実確認原則）
- `~/.claude/skills/docwright/references/boundaries.md`（他文書との責務分離）

## 対象と情報収集

対象読者は新規参加者・貢献者。セットアップ手順・依存関係・起動コマンドは、package.json・Makefile・Dockerfile・CI設定ファイル等のソースから実際に確認し、**推測で手順を作らない**。動作未確認の手順は「未検証」と明示する。

## 新規作成

1. 既存の README 配置慣習（リポジトリ直下、`docs/` 配下等）に従う。無ければユーザーに保存先を確認する。
2. 次の構成で執筆する。
   - 概要 — 何をするリポジトリか、誰向けか
   - セットアップ手順 — 依存関係のインストールから起動確認までの実行可能なコマンド列
   - 使い方 — 典型的な利用シナリオ
   - ディレクトリ構成 — 主要ディレクトリと役割（表またはASCIIツリーで表現する）
   - ドキュメント目次 — 下記の手順で構築する（見つからなければセクション自体を作らない）

## ドキュメント目次の構築

README単体では他の設計書・手順書の存在に気づけないため、`docs/` 直下に実際に存在する関連ドキュメントへのリンク一覧を作る。`docs/` が無ければこのセクション自体を作らない。

1. `docs/` 直下（サブディレクトリは対象外）をGlob/Grepで探索し、README以外のMarkdown文書を洗い出す。
2. 見つかった各文書の先頭見出し（H1）からタイトルを取得する。中身を推測でタイトル付けしない。
3. 可能であれば docwright の17タイプ（要件定義書・ADR・API仕様書等）のどれに該当するか、内容から推定してフェーズ別（企画・要件／設計／実装／テスト／運用／利用者向け）にグルーピングする。推定できないものは「その他」にまとめる。
4. README基準の相対パスで `[タイトル](相対パス)` 形式のMarkdownリンクとしてREADMEに埋め込み、GitHub上でクリック可能なリンクにする。対象文書が1件も見つからない場合はこのセクションを作らない。

## 既存更新

1. 既存READMEの記載（依存バージョン・コマンド・ディレクトリ構成）とソースコードの現状を突き合わせ、乖離箇所を洗い出す。
2. 乖離箇所のみを更新し、記述の意図（表現方針・対象読者のレベル）が明確な既存箇所は書き換えない。
3. ドキュメント目次セクションが既にあれば「ドキュメント目次の構築」の手順で再探索し、新規追加・削除された文書を反映する。無くて対象文書が見つかった場合は新設する。

## docwright:readme と doc-updater の関係

`~/.claude/agents/doc-updater.md` はREADMEがソースコードとの同期がずれやすい前提で汎用フローを担っており、役割は近いが競合しない。docwright:readmeは体系17タイプの一部として、doc-updaterは既存の汎用フローとして、どちらから呼ばれても`references/`を共有することで同じ品質になる。

## 執筆後

自分では整合確認・可読性確認を確定させない。執筆完了をMainに報告し、`doc-verifier`・`review-doc-readability`への委譲を促す。
