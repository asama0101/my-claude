# docwright:update — ドキュメント更新

あなた（Main）は司令塔に徹する。実際の執筆は行わない。対象文書タイプを確定し、`docwright:<name>`の専用agentへ既存更新をdispatchし、完了後に検証を委譲するだけの薄いレイヤーである。

体系の定義（17タイプ・agent名・存在確認の観点）は `~/.claude/skills/docwright/references/taxonomy.md` を参照する。このファイルを最初に読むこと。

## 引数で文書タイプが指定された場合

1. 引数が`taxonomy.md`の17タイプのagent名（`docwright:`以降の部分）のいずれかに一致するか確認する。一致しなければ推測せず、17タイプの一覧を提示して再指定を求める。
2. 対象文書が存在するか確認する。存在しない場合は更新せず、「まだ存在しないため`/docwright:create <doc-type>`を使ってください」と案内して終了する。
3. 存在すれば、該当agentを既存更新モードで起動する。

## 引数なしで呼び出された場合

1. `taxonomy.md`の17タイプそれぞれについて、対応する文書が既に存在するか確認する（`taxonomy.md`の「確認する場所」列を流用してよい）。
2. 存在する文書のうち、ソースコード側に変更がありそうなもの（関連ディレクトリの更新日時、対応するコードの追加・変更）を優先候補として洗い出す。判断材料が乏しい場合は「全件」を候補にしてよい。
3. 候補一覧（対象文書・推定される乖離箇所）をユーザーに提示し、承認を得る。推測で承認前に書き始めない。
4. 承認された文書タイプに対応するagentを既存更新モードでdispatchする。相互依存の無い文書は並列起動する。`docwright:readme`が候補に含まれる場合は必ず最後にdispatchする（他文書の更新結果を目次に反映するため）。

## 検証への委譲

各agentの更新完了後、Mainが`doc-verifier`（事実照合）と`review-doc-readability`（可読性）を並列起動する。不一致・要改善があれば元のagentに差し戻す。

## 参照ファイル

`~/.claude/skills/docwright/references/{writing,source-of-truth,boundaries}.md`は各生成agentが個別に読むため、ここでは読み込まない（オンデマンド原則）。
