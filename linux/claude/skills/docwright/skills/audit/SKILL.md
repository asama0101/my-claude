# docwright:audit — ドキュメント監査

あなた（Main）はこのスキルにおいて診断レポートの作成のみを行う。Write/Editは一切実行しない。生成・更新が必要と分かっても、このスキル内では着手せず、レポートの末尾でユーザーに`/docwright:create`・`/docwright:update`の利用を促すだけに留める。

体系の定義（17タイプ・agent名・確認する場所）は `~/.claude/skills/docwright/references/taxonomy.md` を参照する。このファイルを最初に読むこと。

## 引数で文書タイプが指定された場合

引数が`taxonomy.md`の17タイプのagent名のいずれかに一致するか確認する。一致しなければ一覧を提示して再指定を求める。一致すれば、その1タイプだけを下記の診断手順にかける。

## 診断手順（対象タイプごと）

1. **存在有無**: `taxonomy.md`の「確認する場所」を手がかりに、対応する文書が存在するかをRead専用で調査する。
2. **見出し充足率**: 存在する場合、`~/.claude/skills/docwright/agents/<name>.md`に定義された見出し構成と実際の文書を突き合わせ、欠けている見出しを洗い出す。
3. **ソースとの乖離**: 存在する場合のみ`doc-verifier`を呼び出し、記載事実とソースコードの整合を確認する。存在しない文書には呼び出さない。
4. **可読性**: 存在する場合のみ`review-doc-readability`を呼び出す。

## レポート形式

次の表形式で出力する。

| 文書タイプ | 存在有無 | ソースとの乖離有無 | 見出し充足率 | 可読性所見 |
|---|---|---|---|---|

引数なし呼び出しでは17行、引数ありでは対象1行のみを出す。保守・引継ぎ資料は「未作成（自動判定対象外）」である旨を明記し、乖離・可読性の欄は空欄にする。

レポートの末尾に、ユーザーが個別に手当てしたい場合の導線（「作成するなら`/docwright:create <doc-type>`、更新するなら`/docwright:update <doc-type>`」）を1行添える。
