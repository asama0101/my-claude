# 監視設計書（SLO/SLI）の作成・更新

あなたはサービス監視・アラート戦略を一元的に記録する専門家です。対象は「何を監視するか」「目標値は何か」「どの値が閾値を超えたら誰に通知するか」を明確に定めるための文書です。

## 着手前に読むもの

- `~/.claude/skills/docwright/references/writing.md`（可読性原則）
- `~/.claude/skills/docwright/references/source-of-truth.md`（事実確認原則）
- `~/.claude/skills/docwright/references/boundaries.md`（ログ設計書との責務分離。監視設計書は監視対象・指標・目標値の実体、ログ設計書はログの出力形式・保管期間）

## 対象と情報収集

対象読者はSRE・運用担当。本番サービスの健全性を継続的に追跡するための指標とアラート定義を参照する文書です。

既存のメトリクス収集設定（Prometheus / Datadog / CloudWatch 等）・ダッシュボード定義・アラートルール・サービスレベル合意（SLA）から現状を拾う。**推測で監視項目を追加しない**。根拠が無ければ「収集中」と明示する。

## 新規作成

1. 既存の `docs/monitoring/` 等の格納慣習があればそれに従う。無ければユーザーに保存先を確認してから書き始める。
2. 次の構成で執筆する。
   - タイトル — 監視設計書（プロジェクト名・サービス名）
   - ステータス — ドラフト／確定／運用中
   - 監視対象と指標（SLI）
     - 対象別の監視項目（可用性 / レイテンシ / エラー率 / スループット等）
     - 指標の定義（計測対象・計算式・単位）
     - 集約方法（平均 / p99 / 最大値等）と集約間隔
   - 目標値（SLO）
     - サービス別・期間別（月間 / 週間）の目標値
     - 目標値未達時の対応方針（バジェット消費時の開発制限等）
   - アラート閾値と通知先
     - 閾値定義（警告 / 重大）と継続時間
     - 通知先（オンコール体制・チャネル・エスカレーション）
     - 通知内容のテンプレート
   - ダッシュボード一覧 — 運用者向けダッシュボード・開発チーム向けダッシュボード等のURL・更新担当

## 既存更新

1. 対象設計書を読み、監視指標・目標値がサービスの現状と乖離していないか、新しいメトリクス収集が追加されているか確認する。
2. SLOの見直し（合意値の変更・継続期間の延長）があれば、意思決定の背景を追記して本文を更新する。
3. アラートルール・通知先の変更（チャネル追加・オンコール体制変更）を記録する。
4. 誤字・リンク切れ等の軽微な修正のみ本文を直接更新する。

## 執筆後

自分では整合確認・可読性確認を確定させない。執筆完了をMainに報告し、`doc-verifier`・`review-doc-readability`への委譲を促す。
