# docwright:create — ドキュメント新規作成

あなた（Main）は司令塔に徹する。実際の執筆は行わない。対象文書タイプを確定し、`docwright:<name>`の専用agentへ新規作成をdispatchし、完了後に検証を委譲するだけの薄いレイヤーである。

体系の定義（17タイプ・agent名・自動判定チェックリスト・dispatch順序の注意）は `~/.claude/skills/docwright/references/taxonomy.md` を参照する。このファイルを最初に読むこと。

## 引数で文書タイプが指定された場合

1. 引数が`taxonomy.md`の17タイプのagent名（`docwright:`以降の部分）のいずれかに一致するか確認する。一致しなければ推測せず、17タイプの一覧を提示して再指定を求める。
2. 対象文書が既に存在するか確認する。存在する場合は作成せず、「既に存在するため`/docwright:update <doc-type>`を使ってください」と案内して終了する（作成と更新の境界を曖昧にしない）。
3. 存在しなければ、該当agentを新規作成モードで起動する。

## 引数なしで呼び出された場合

1. `taxonomy.md`の判定チェックリストに従い、各文書タイプについて「候補に入れる条件」を満たすか確認する。保守・引継ぎ資料は自動判定に含めない。
2. 既に存在する文書タイプは候補から除外する（作成ではなく更新の対象のため）。
3. 候補一覧と各判定根拠をユーザーに提示し、承認を得る。推測で承認前に書き始めない。
4. 承認された文書タイプに対応するagentを新規作成モードでdispatchする。相互依存の無い文書は並列起動する（例: セキュリティ設計書とテスト計画書は独立）。依存がある場合は順序を明示する（例: 詳細設計書はデータモデル確定後）。`docwright:readme`が候補に含まれる場合は必ず最後にdispatchする（`taxonomy.md`のdispatch順序の注意を参照）。

## 検証への委譲

各agentの執筆完了後、Mainが`doc-verifier`（事実照合）と`review-doc-readability`（可読性）を並列起動する。不一致・要改善があれば元のagentに差し戻す。

## 参照ファイル

`~/.claude/skills/docwright/references/{writing,source-of-truth,boundaries}.md`は各生成agentが個別に読むため、ここでは読み込まない（オンデマンド原則）。
