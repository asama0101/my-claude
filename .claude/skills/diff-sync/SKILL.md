# diff-sync

`linux/claude/` と `windows/claude/` は本来同じ設定のミラーだが、Windows対応コード（Git Bash向けのパス正規化・ロケール対応など）のように意図的にOSごとで内容が異なってよい箇所がある。このスキルは、その「意図的な差分」を台帳（`ledger.json`）に記録して次回以降は自動的に許容し、台帳に無い・変化した差分だけを人間の判断に上げる。

**実機（`~/.claude/` や `%USERPROFILE%\.claude\`）には一切触れない。** 比較対象はリポジトリ内の `linux/claude/` と `windows/claude/` の2つだけ。

## sync-configとの違い（重要）

- `sync-config`: 実機 → ミラー の一方向コピー。差分の意味は判定しない。
- `diff-sync`（このスキル）: ミラー同士（linux/claude vs windows/claude）を比較し、差分が意図的か未確認かを判定・記録する。

CLAUDE.mdのGotchas「`linux/claude/`・`windows/claude/` を直接編集しない」は sync-config による上書きを想定した注意であり、**このスキルは両ミラーの差分を解消するために両ミラーを直接編集してよい**（このスキル自身の目的そのものであるため）。

## モード1: 通常実行（差分の検出・解消）

デフォルトのモード。次の手順で進める。

1. `bash <スキルディレクトリ>/scripts/detect-diffs.sh` を実行する。出力は次の形のJSON:
   ```json
   {
     "new_diffs": [{"file": "...", "linux_hash": "...", "windows_hash": "..."}],
     "known_diffs": [{"file": "...", "linux_hash": "...", "windows_hash": "...", "reason": "...", "recorded_at": "..."}],
     "only_in_linux": ["..."],
     "only_in_windows": ["..."]
   }
   ```
   `known_diffs` はすでに台帳に記録済みの差分なので、そのままユーザーに件数だけ触れれば十分で、逐一確認する必要はない。以下は `new_diffs` と `only_in_*` の処理。

2. **`only_in_linux` / `only_in_windows` の各エントリ**について、実際の内容（ファイルなら中身、ディレクトリなら配下構成）を確認した上でユーザーに3択を確認する:
   - **コピー**: 欠けている側に同じ内容を作る
   - **削除**: 存在する側から取り除く
   - **許容**: 片方にしか無いことが意図的（台帳に記録するのみ、何も変更しない）

3. **`new_diffs` の各エントリ**について、`diff <(tr -d '\r' < linux/claude/<file>) <(tr -d '\r' < windows/claude/<file>)` 等で実際の差分内容を確認し、事実に基づく所見（どちらが最新か、矛盾はないか）を添えてユーザーに4択を確認する:
   - **A**: linux側の内容を採用（windows側をEditで合わせる）
   - **B**: windows側の内容を採用（linux側をEditで合わせる）
   - **C**: 両方の内容を活かして手動マージ（両側をEditで同じ内容にする）
   - **D**: 意図的なOS差分として台帳に許容記録（理由をユーザーに確認し、ファイルは変更しない）

   `new_diffs` が複数件あるときは、個別確認に加えて「今回検出された new_diffs を全部Dで一括処理する」という一括承認の選択肢も提示する。個別に確認したいものだけユーザーに除外してもらってよい。

4. **A〜Cを選んだ場合**: Editで実際に反映する。反映後、両ファイルの正規化ハッシュを再計算し（`tr -d '\r' < <file> | sha256sum | cut -d' ' -f1`）、一致していることを確認する。一致した場合は差分が解消されたということなので、台帳への記録は不要（同一内容になったファイルは次回 `detect-diffs.sh` で `new_diffs`/`known_diffs` どちらにも出てこなくなる）。

5. **Dを選んだ場合**: 台帳に追記する。既存エントリは残したまま追記する（上書きしない。これがそのまま変更履歴になる）:
   ```bash
   jq --arg f "<file>" --arg lh "<linux_hash>" --arg wh "<windows_hash>" --arg r "<理由>" --arg d "$(date +%F)" \
     '. + [{file:$f, linux_hash:$lh, windows_hash:$wh, reason:$r, recorded_at:$d}]' \
     <スキルディレクトリ>/ledger.json > <スキルディレクトリ>/ledger.json.tmp \
     && mv <スキルディレクトリ>/ledger.json.tmp <スキルディレクトリ>/ledger.json
   ```

6. 「コピー」「削除」を選んだ `only_in_*` エントリも実際にファイル操作を行う。

7. 最後に `git status` を表示して終了する。**このスキル自身はcommit・pushを行わない。** 差分があれば「commit・pushが必要なら `/pr-create` を使ってください」と伝える。

## モード2: 台帳表示

ユーザーが台帳の中身を見たい・許容差分の履歴を確認したいと依頼した場合は、他の処理をせず次を実行して結果をそのまま提示する:

```bash
bash <スキルディレクトリ>/scripts/show-ledger.sh
```

同じファイルパスに複数エントリがある場合は記録日順に並んで出力されるので、そのまま「このファイルはこう変遷してきた」という履歴として読める。

## 注意

- 改行コード(CRLF/LF)の違いだけの差分はノイズとして扱う。`detect-diffs.sh` は比較前に `tr -d '\r'` で正規化してからハッシュを取るため、そもそも差分として出てこない。
- 台帳のハッシュ判定はファイル単位・内容完全一致ベース。ファイルの一部だけが変わっても、そのファイル全体が「新規差分」として再検出される（ハンク単位では管理しない）。
- `only_in_linux` / `only_in_windows` の判定はファイルに加えて空ディレクトリも対象にする。中身のあるディレクトリが片方にしかない場合は、配下の各ファイルが自然に `only_in_*` へ出てくる。
